# Wolverine Intelligence Platform
## Database Specification & 3-Domain Architecture (DATABASE.md)

This document defines the PostgreSQL database architecture, Prisma ORM integration, complete ER model, and developer operability guide for the Wolverine Intelligence platform.

---

## 1. The Three-Domain Architecture Overview

The system strictly decouples its data layers across three distinct domains:

```
┌─────────────────────────────────────────────────────────────┐
│ DOMAIN A: Research Data Lake (Filesystem: research-data/)   │
│ - Raw research archives, manifests, profiling reports       │
│ - Normalized train/val/test splits, feature extraction      │
│ - Synthetic calibration distributions (NOT in PostgreSQL)   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ DOMAIN B: Operational Intelligence Database (PostgreSQL 15) │
│ - RESEARCH METADATA: datasets, model_versions               │
│ - OPERATIONAL INTELLIGENCE: actors, personas, identifiers,  │
│   observations, artifacts, relationships, scans, findings   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ DOMAIN C: Wolverine Cryptographic Trust Store (Besu)        │
│ - wolverine_evidence, trust_receipts, Merkle roots, anchors │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. PostgreSQL Table Categorization

### Category 1: Research & Model Metadata Tables
- `datasets`: Registered research dataset metadata catalog (provenance, license, usage, hash).
- `model_versions`: Registered baseline models, hyperparameter configurations, and evaluation metrics.

### Category 2: Operational Intelligence Graph Tables
- `networks`, `portals`, `assets`: Physical and overlay infrastructure endpoints.
- `actors`, `personas`, `accounts`: Threat identity resolution hierarchy.
- `identifiers`: Unified typed identifiers (HANDLE, PGP_KEY, WALLET, EMAIL, etc.).
- `artifacts`, `observations`: Raw collected bytes and canonical structured observations.
- `relationships`, `relationship_evidence`: Multiclass graph edges citing supporting evidence.
- `scans`, `findings`, `infrastructure_indicators`: Automated network intelligence detections.
- `attribution_candidates`, `attribution_evidences`, `attribution_features`: Scored link candidates and feature vectors.
- `behavior_profiles`, `stylometric_profiles`, `timeline_events`: Behavioral and linguistic profiles.
- `ai_hypotheses`: Advisory explanations generated by the AI reasoning layer.

### Category 3: Wolverine Cryptographic Trust Tables
- `wolverine_evidence`: Merkle root attestations and SHA-256 observation signatures.
- `trust_receipts`: Hyperledger Besu on-chain transaction hashes and block numbers.

## 3. Developer Operability Commands

```bash
# Start Database Container
npm run db:up

# Stop Database Container
npm run db:down

# Apply Migrations
npm run db:migrate

# Seed Deterministic Development Fixture
npm run db:seed

# Inspect Database Records in Terminal
npm run db:inspect

# Research Data Lake Commands (Domain A)
npm run dataset:status    # View registered datasets
npm run dataset:verify    # Verify SHA-256 file checksums
npm run dataset:profile   # Generate field and text profiles
npm run features:extract  # Deterministic feature extraction

# Run Full Test Suite (Database + Research Data Lake)
npm test

# Open Web GUI
npm run db:studio
```
